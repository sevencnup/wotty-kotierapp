# 内网连接卡住问题开发记录

## 目标

排查并解决 EasyTier Android 客户端启动 VPN 后页面长期显示本机 [?25lIP --[?25h、无法进入内网段的问题。

## 当前现象

- native 网络实例启动成功。
- Android [?25lVpnService.Builder.establish()[?25h 成功。
- [?25lEasyTierJNI.setTunFd()[?25h 返回成功。
- 首页节点列表能显示本机，但本机虚拟 IP 为空。
- 用户反馈服务器 TCP 端口可达，但内网段不可访问。

## 执行步骤

1. 检查 native 状态查询接口、JSON-RPC 响应及节点解析逻辑，确认本机节点识别和虚拟 IP 字段来源。
2. 检查 VPN 启动参数获取时机、地址兜底值和路由提取逻辑，确认 TUN 地址与内网段路由是否有效。
3. 建立能够覆盖实际故障边界的回归测试，先验证失败现象。
4. 按最小范围修复，补充必要日志，删除临时调试代码。
5. 执行测试、debug 构建或可行的 Android 校验，并确认不存在遗留调试进程。
6. 更新版本记录并在本地仓库提交；不推送 GitHub。

## 验收标准

- 启动后本机节点能够显示有效的虚拟 IP。
- TUN 接口使用有效地址建立，不依赖无效的固定兜底地址。
- 从 native 返回的代理/内网 CIDR 能正确转换为 Android VPN 路由。
- 相关回归测试通过，Android 工程能够完成对应构建或给出明确的环境阻塞原因。

## 已完成

- 首页 DHCP 启动流程不再使用固定 `10.144.144.1` 作为兜底；未拿到真实虚拟 IP 时会停止网络实例、刷新运行态并取消 VPN 启动。
- 网络配置页的 VPN 授权回调同步移除固定地址兜底。
- `EasyTierVpnService` 拒绝空 IPv4 参数，避免其他入口建立无效 TUN。
- 新增 `VpnStartPolicyTest`，覆盖 DHCP 空地址、静态 IPv4 和 native 已分配 IPv4 三种情况。
- 已确认真机 native 侧仍有独立连接问题：`tcp://104.194.66.213:11010` TCP 可达，但 peer 握手后立即移除，`secure_auth_level=0`、无路由，导致 DHCP 地址保持 `null`。该问题需要核对入口服务器、网络密钥及服务端 EasyTier 状态，不能由 Android UI 兜底解决。

## 验证结果

- `:app:testDebugUnitTest`：通过。
- `:app:compileDebugKotlin`：通过，仅保留既有 deprecated/unused warning。
- 真机旧版本 `4.2.46 (4068)` 未被覆盖；修复版本使用 `4.2.47 (4069)`。
