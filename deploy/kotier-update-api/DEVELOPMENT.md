# Kotier 更新服务缓存改造开发记录

## 目标

让更新服务继续从 GitHub Release 获取最新版本号和更新说明，同时把 APK 下载到服务器缓存，并统一通过 `k.wotty.app` 提供下载。历史兼容入口仅用于接收旧客户端的更新检查请求，返回内容仍使用 `k.wotty.app`。

## 实施步骤

1. 更新 Node 服务：读取 GitHub 最新 Release，生成固定的 `k.wotty.app` 自有下载地址。
2. 增加 APK 缓存目录、临时文件原子落盘、并发下载复用和 HTTP Range 支持。
3. 更新 Compose 持久化挂载，保证容器重启不会丢失已缓存的安装包。
4. 本地执行语法检查和接口/下载行为验证。
5. 通过 Ops Control 更新服务器项目并检查服务状态。
6. 验证新域名和历史兼容入口返回的版本信息、APK 下载和断点范围请求，确保返回内容均为 `k.wotty.app`。
7. 更新版本记录并提交本地 Git；仅在用户明确要求时推送到 GitHub。

## 约束

- 不覆盖历史版本 APK。
- APK 只在完整下载后从 `.part` 文件原子改名为正式文件。
- GitHub Release 正文作为更新说明来源。
- 历史兼容入口继续接收旧版客户端，但不会在 API 返回内容或更新说明中展示旧域名。
- 下载接口只公开当前 GitHub Release 的 APK；历史缓存文件保留在服务器上，但旧版本直链返回 404，便于下架错误或不安全的安装包。

## 4.2.45 升级说明域名统一（2026-09-16）

### 目标

将 4.2.45 客户端升级至 4.2.46 时读取的 `release_notes`、`download_url` 和 GitHub Release 更新说明统一为 `k.wotty.app`。

### 实施与验证

1. 将 GitHub Release 正文模板中的项目网站、更新接口和下载地址替换为 `k.wotty.app`。
2. 将兼容更新 API 的公共下载域名固定为 `https://k.wotty.app`，无论请求来自哪个历史入口。
3. 更新已发布的 GitHub `v4.2.46` Release 正文，不创建新版本或替换 APK。
4. 部署 API 后请求历史兼容入口的 `/version.json`，确认 JSON 内不再出现旧域名。
